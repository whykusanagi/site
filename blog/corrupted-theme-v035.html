Corrupted Theme 0.3.5: even the errors belong here

Published 22 October 2026 · HTTP error pages with the same identity as the rest of the site.

TL;DR

  • 20 HTTP error pages, from 400 to 503, with shared styling and a different line of copy for each status.
  • Two ways to use them: standalone HTML documents, or exported status data and CSS for your own renderer.
  • One preview gallery to browse every design before wiring it into your site.
  • Your host still sets the response status. Installing the package supplies the pages; connecting them to real failures is a site-level decision.

The design system reaches the dead ends

A missing page is still a page on your site. So is a denied request, a timeout, or a service that cannot answer right now. Those moments deserve the same visual identity as everything that loaded successfully.

Corrupted Theme 0.3.5 is now on npm, and this release brings those failure states into the package: dark backgrounds, oversized glowing status numbers, readable supporting text, and pink-to-purple navigation links. The number scales down on smaller screens, and the links have visible keyboard focus styles.

The layout stays direct. A visitor gets a status, a title, a message, and a way home. The personality lives in the copy.

20 codes, 20 different ways to lose the connection

The set covers familiar responses like 401, 403, 404, 429, 500 and 503, alongside less common ones like 418 and 451. Each keeps its recognizable status title and gets its own Corrupted Theme line.

  • 404 / Page Not Found: “I wasn't where you were looking. I never was.”
  • 409 / Conflict: “That version of you is no longer supported.”
  • 418 / I'm a Teapot: “I told you exactly what I was. You chose not to listen.”

There is also a generic fallback for codes outside the map: “Something went wrong in this reality.” The status explains the failure; the line makes it feel like it belongs here.

Drop in a page, or keep your own renderer

The package ships self-contained documents at errors/<code>.html. Each embeds its styles and includes a default home link, so the error screen does not need a separate stylesheet request to render.

For site-specific navigation or server-rendered pages, use the shared copy directly:

import { getHttpError } from '@whykusanagi/corrupted-theme/http-errors';

const { title, line } = getHttpError(404);

The httpErrors export exposes the complete map. getHttpError(code) returns the matching entry or the generic fallback. Your renderer decides where the text goes and which recovery links make sense for that site.

The main theme already includes the error styles. If you only need this module, load the tokens first:

@import '@whykusanagi/corrupted-theme/variables';
@import '@whykusanagi/corrupted-theme/error-pages-css';

Five classes provide the structure: .error-page, .error-code, .error-title, .error-line and .error-links. The preview gallery puts all 20 designs on one page.

Give the page the right HTTP status

A file named 404.html can still be served with a 200 response. The filename supplies no HTTP semantics by itself: your host or server needs to return the correct status when it serves the page.

The standalone documents include noindex, nofollow metadata. For custom rendering, the integration guide covers navigation, response handling, and the embedded stylesheet's CSP requirements.

Get 0.3.5

npm install @whykusanagi/corrupted-theme@0.3.5

This release brings a focused addition to the design system: a shared place for error styling, status copy, and ready-made pages. The next time a connection fails, the site can keep its identity all the way to the recovery link.

Ask Celeste

Q: Does installing 0.3.5 replace my site's error pages automatically?
A: No. You get the assets and exports, then connect them to your host's error handling. I can supply the missing-page existential crisis. Your server still has to send the 404.

Q: Can I keep my own navigation and change the message?
A: Yes. Render your own HTML with the exported CSS, use the shared copy where it fits, and choose links that help your visitors recover. Escape dynamic values before inserting them into HTML.

Q: What happens if my status code is not one of the 20?
A: getHttpError() returns the generic title and message. Your handler keeps the real response status; the fallback gives the page something readable to say.
